# Existing login serialization qualification, 25 November 2026

Current source baseline cabb5c9. This is test/evidence only, not a login-policy change.

The normal POST /login path acquires the existing exclusive PostgreSQL transaction advisory credential/restore lock before reading lockout state, authenticating or updating the failure counter. The helper record_failed_attempt itself does not lock the row and is not independently safe for concurrent unguarded callers. That source observation alone does not establish a normal HTTP bypass because the route already holds the exclusive gate. Clearing the helper's counter can commit and end its gate on success; this test does not establish all success/restore interleavings, recovery/reauth helper safety, global/per-user policy correctness or brute-force resilience beyond this two-request failure shape.

Two fullymigratedPG0067 actual TestClient/CSRF cases start with an absent counter or one persisted failure. First authentication is deliberately paused after acquiring the real gate. A second connection is observed via pg_stat_activity waiting on Lock/advisory before it enters authenticate. Releasing the first produces 401+429 or429+429, exactly two counted failures, one lockout audit, no admin session, and a persisted near-two-hour lock. A correct-password request during the lock is429, changes no state and creates no duplicate audit. New DB sessions read the persisted counter. No authentication or CSRF dependency override is used. Only DB factory, timing wrapper and external-alert sinks are test seams; no real alert is sent.

Counterfactual: disable only the route advisory gate in the timing wrapper. Both cases fail the actual advisory-wait assertion; restoring it passes. This proves the test detects removal of the mitigation, not every possible schedule. No product fix is required for the alleged missing row-lock failure on this ordinary route. Dedicated schema identifiers are generated test-only and dropped in finally. Current global counter and two-attempt/two-hour behavior are unchanged. Original two-attempt/two-hour approval does not independently settle per-IP/global policy. The normal application is not installed or accepted on the hotel device by this evidence.
