## Contract, not live protocol

`app/snapshot_codec.py` is a pure unused technical primitive. No product caller, DB write, route, cache, file export, device channel, journal, receipt, role rule or epoch integration is added. SHA256 is public integrity data, not authentication/permission. Decoder success does not authorize disclosure. Mutable returned dict is caller-owned internal data.

Version1 canonical compact sorted-key UTF8 JSON explicitly tags None/bool/int/float/Decimal/str/date/aware datetime. Exact supported scalar types only; no default=str or arbitrary containers. Preserve Decimal sign/scale, negative float zero, date/datetime distinction, offset/microseconds and Unicode codepoints. No zone-name reconstruction. Reject duplicate/extra keys, unknown tags/versions, malformed UTF8, surrogates, nonfinite values, unsupported types, noncanonical byte forms and hostile nesting with controlled supported-input failures. Canonical decode ends by re-encoding and requiring exact original bytes.

Bounds selected for this isolated engineering format, not user business policy:128fields,1..128codepoint names,262144encoded bytes,1000integer/Decimal digits,absolute Decimal exponent<=1000. Byte bound is checked before parsing; encode builds the JSON before its final byte check, so this is not a hard preallocation-memory cap. Exact datetime objects can contain arbitrary custom tzinfo methods; ValueError/TypeError/OverflowError offset failures are controlled, but arbitrary application-defined tzinfo exceptions/side effects are not a universal sandbox guarantee. Product snapshots use ordinary database-derived datetime offsets; do not execute untrusted tzinfo code as data. No claim that every imaginable Python object is contained.
